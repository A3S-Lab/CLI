# a3s-code v8.4.0 — first-principles capability integration tests

**Runtime pin:** `a3s-code-core = 8.5.1` (Code TUI host in `crates/cli`).  
**Living matrix:** [`capability-test-matrix.md`](./capability-test-matrix.md)  
**Full TUI plan (refuse overfit):** [`tui-first-principles-test-plan.md`](./tui-first-principles-test-plan.md)  
**Architecture audit:** [`capability-first-principles-review.md`](./capability-first-principles-review.md)

## Objective

Prove that the four v8.4.0 integration surfaces are **effective**, **efficient**, and
**UI/UX-correct** for the product loop (user → agent tools → evidence → next turn),
without false completeness from prompt-string tests alone.

| Capability | Mission (must strengthen) | Efficiency invariant | UX contract |
| --- | --- | --- | --- |
| zvec / BM25 + grep | Local lexical retrieval | Grep never opens durable zvec; BM25 opens on demand | Footer / Explored cards must not imply “index always ready” |
| ReMe-like memory | Durable recall/extract | Lazy `~/.a3s/memory` — no first-frame I/O | `/memory` tip → `/ctx memory`; panel loading + browse |
| Reviewer | Independent claim↔record | `ReviewerLane` only; never main turn queue | Sticky ≠ git `/review` chrome; mode chip; bus copy |
| Moli `web_search` | Default headless SERP | Tool registered always; binary on first headless use | Fail-closed / cascade visible in tool chrome |

## Gates (every case)

1. **Mission** — serves the core coding loop.  
2. **Effectiveness** — seeded truth detected; false success rejected.  
3. **Efficiency** — demand-driven, bounded, non-blocking.  
4. **UX** — what the user sees matches the product contract.  
5. **Evidence** — hermetic automated test, or named ignored live test.

Prompt-inclusion tests prove *evidence packaging*, not *LLM verdict correctness*.
Mark those as **Effect (prompt)**; reserve **Effect (detect)** for fixture+mock or live.
